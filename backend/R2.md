# Profile photos in Cloudflare R2

Create a private R2 bucket and an R2 API token scoped to that bucket with object read/write permissions. Set these on the backend only:

```dotenv
R2_ACCOUNT_ID=your_cloudflare_account_id
R2_ACCESS_KEY_ID=your_r2_access_key_id
R2_SECRET_ACCESS_KEY=your_r2_secret_access_key
R2_BUCKET=your_private_bucket_name
R2_KEY_PREFIX=nutrifact
```

Restart the backend. `POST /profile/photo` accepts an authenticated multipart form field named `photo` (JPEG, PNG, or WebP, up to 5 MB). The backend checks file signatures, uploads to R2, stores the object key on the user, and removes the replaced object. `GET /profile` returns a one-hour signed photo URL. R2 credentials are never sent to the mobile app.

Objects are organized under `nutrifact/users/<user-id>/profile/avatar/<uuid>.<ext>` by default. Set `R2_KEY_PREFIX` to a different path such as `development/nutrifact` for another environment. R2 folders are key prefixes, so they appear automatically when the first object is uploaded; no separate folder-creation request is needed. Existing saved photo keys continue to work and are removed when users replace their photos.
